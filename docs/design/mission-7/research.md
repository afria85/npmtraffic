# Reference research

Sources inspected on 2026-11-16. The comparison uses documented product behavior and the live or documentation interfaces where accessible.

| Reference | What solves a problem | Adapt for npmTraffic | Avoid |
| --- | --- | --- | --- |
| [Plausible guided tour](https://plausible.io/docs/guided-tour) | One view with an essential overview makes reporting easy to enter. | Put the plot in the analysis path and keep supporting numbers compact. | Copying its KPI arrangement or borrowing website-specific language. |
| [Grafana time series](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/time-series/) | Legends, series options and explicit null handling make a plot diagnosable. | Show the actual line pattern in the legend and keep gaps visible. | A persistent configuration panel ahead of the data. |
| [Chrome Modern Web Guidance](https://developer.chrome.com/docs/modern-web-guidance/get-started) and [v1.0 announcement](https://developer.chrome.com/blog/modern-web-guidance-v1) | Baseline compatibility and use-case guidance help match tools to tasks. | Use native semantic controls and stable CSS grid/flex for reflow. Keep client boundaries focused on interactivity. | Treating a new browser API, plugin or JavaScript scheduler as a layout dependency. Official web guidance was used directly. |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | Reflow, contrast, focus visibility, target size and label requirements turn usability into checkable constraints. | Test narrow and enlarged text layouts, leave a visible focus ring, and use text for coverage and freshness. | Using color alone or treating a tooling pass as accessibility conformance. |
| [WAI slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) | A defined keyboard model supports point-by-point inspection. The guidance also identifies touch assistive-technology risks. | Preserve the native observation control and the daily table alternative. | Introducing a custom slider or swapping visual order with CSS in a way that conflicts with keyboard order. |
| [Core Web Vitals](https://web.dev/articles/vitals) | LCP, INP and CLS make perception, interaction and stability visible as distinct problems. | Use comparable baseline and candidate samples. Identify layout distance and insertion delay separately. | Using lab timings to claim field p75 compliance. |
| [npm trends](https://npmtrends.com/) | The target workflow is entering package names and comparing them on one timeline. The direct request returned HTTP 403 in this environment. | Preserve straightforward multi-package entry and reproducible Compare URLs, using npmTraffic’s own observed UI as evidence. | Claiming a current live visual comparison or copying a third-party interface. |
| [Canonical npmTraffic audit](https://app.notion.com/p/4172c266720a81b0a0d6efb4d09529a1) | The existing audit ties adoption to observation integrity, measurable performance and unchanged security boundaries. | Keep defaults and data paths stable, document fixture versus live behavior, and measure before adoption. | Framework rewrites or production configuration changes for presentational work. |
