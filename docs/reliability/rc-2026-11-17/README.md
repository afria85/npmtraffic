## Reproduce

From a clean checkout of the evidence commit with Node 22, use the locked dependencies and install the Playwright engines as needed.

```sh
npm ci
npm run build
npx tsc --noEmit
npm run lint
npm audit --omit=dev --audit-level=high
npm test
npx playwright install chromium firefox webkit
npm run test:smoke
node --import tsx --test tests/npm-range.test.ts tests/data-integrity.test.ts tests/compare.test.ts
node scripts/verify-webkit-navigation-local.mjs ./test-results/rc-navigation
```

The runner starts an isolated production build with npm fixture responses, and an existing loopback-only HTTP adapter for WebKit. The adapter strips `upgrade-insecure-requests` from the loopback response because WebKit otherwise upgrades fixture subresources. Hosted responses and deployment protection are untouched. After one post-fix matrix completed, its fixture-only proxy tried to write a second response status during shutdown. The wrapper now destroys an already-started response on upstream error and closes proxy connections before stopping Next. The proxy crash occurred after all functional cases and does not explain the RSC exceptions observed earlier in that run. Browser trace files contain request paths and selected transport fields. The RSC query key is hashed. CSV bytes are read to verify the header and columns, then discarded. The first expanded development run failed because the test seeded two packages while asserting five. The corrected fixture seeded all five and passed on the same application build.

- **VERIFIED (#29).** The 65,536-byte boundary counts decoded stream bytes. Focused tests covered gzip, one-byte-over rejection, absent size headers, body cancellation (including a nonsettling cancellation hook), timeout, invalid/truncated JSON, registry-confirmed 404, cold failure, stale verified recovery, verified zero, unverified observations and absent shared Compare days. The independent misleading-length experiment set `Content-Length: 1` and tested bodies of 65,536 and 65,537 bytes. The exact-cap body returned the verified zero and the oversized body returned the existing invalid-response failure. See [results](bounded-length.json), [the focused npm tests](../../../tests/npm-range.test.ts), and [the original limited live-size sample](../issue-29/range-sample.json). The three prior 365-day sample bodies were 14,751–16,360 decoded bytes. There was no new public upstream sampling.
- **P2 operational exposure, impact unquantified.** Package HTML SSR calls `fetchTraffic` directly and separately retrieves package metadata. Compare HTML may fan out to at most five package download reads plus a shared registry-window request on a cold instance. API rate limiting wraps route handlers and does not admit HTML SSR requests. Five-minute freshness, same-key in-flight deduplication and stale fallback within 24 hours reduce repeat traffic on one instance. They leave cold, high-cardinality and multi-instance traffic as residual exposure. CDN hits may avoid origin work. Platform admission, cache coverage, upstream quota pressure and costs were outside the measured sample. No limiter or infrastructure change follows from this read-only analysis. See [Package SSR](../../../app/p/%5Bname%5D/page.tsx), [Compare reads](../../../lib/compare.ts), [traffic caching](../../../lib/traffic.ts), and [API admission](../../../app/api/v1/compare/route.ts).
- No P0 or P1 product defect was confirmed. API schemas, export formats, and observation semantics have no new runtime changes. Issue #30 seasonality research is separate.

## Confirmed Compare keyboard defect and correction

**P2 — fixed.** On the initial integration build, reverse tabbing on mobile could leave focused actions fully hidden by the sticky site header. Native traversal reproduced this at 320px (package input, Absolute and Indexed) and 390px (Export and Style). The Chromium regression test confirmed that Absolute held focus, while hit-testing its center found the header. CSS scroll padding did not change this browser focus behavior. [Before measurements](focus-before.json) · [reproducible regression](../../../smoke/sticky-header-focus.spec.ts)

The correction preserves native focus and ordering. After a focus change on the populated Compare page, it scrolls just enough to expose a keyboard-visible main-content control when an actual hit-test finds the sticky header over its center. No correction runs when the target is already visible. The update adds `CompareFocusVisibility.tsx`, a marker on the site header, the Compare page entry point and the focused Playwright assertions at 320px and 390px. The test fails on the original application and passes after correction in Chromium. Firefox and WebKit each passed both widths. [WebKit 320px focus](screens/webkit-320-after-focus.webp) · [Firefox 390px focus](screens/firefox-390-after-focus.webp) Chromium native 200% and 400% zoom also kept the target visible after Shift+Tab.
